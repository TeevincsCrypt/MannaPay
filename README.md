# MannaPay

**PayPal checkout. Simplified.**

MannaPay is a browser extension that makes paying with PayPal faster across the web. When you reach a checkout, it detects the purchase, checks whether the store accepts PayPal, and helps you complete the PayPal payment with as few steps as possible.

MannaPay doesn't replace PayPal or add other payment providers, and it doesn't claim a store accepts PayPal when it doesn't. It makes the existing PayPal checkout easier to reach and finish.

## Features

| Feature | What it does |
| --- | --- |
| **Smart checkout detection** | Scores the URL, payment and address fields, checkout buttons and headings to recognize cart and checkout pages, including single-page checkouts that change without reloading. |
| **PayPal detection** | Finds PayPal payment-method options, same-origin "Checkout with PayPal" buttons, and PayPal Smart Buttons (JS SDK / Braintree iframes). Ignores "What is PayPal?" links and footer logos. |
| **One-click assistance** | A small panel on the page, plus the toolbar popup, offers **Pay with PayPal**. MannaPay clicks an express PayPal button, or selects the PayPal payment option. For a Smart Button it highlights the button so you can press it. |
| **Automatic checkout assistance** | Optional setting: automatically select PayPal as the payment method on checkouts that offer it. MannaPay never places an order on its own. |
| **Order recognition** | Reads the merchant name, order total and currency (structured data, Shopify, "Total" rows, the PayPal SDK's currency). It handles `1,234.56`, `1.234,56 €`, `£58.00`, `CA$` and similar formats, and warns when the currency isn't one PayPal supports. |
| **Secure payment confirmation** | Follows the payment to PayPal (same-tab redirect or popup) and back. It detects the merchant's confirmation or cancellation, records the order number, and checks that the confirmed amount matches the checkout total. Results show in the panel, the toolbar badge and **Recent payments**. |
| **Cross-site compatibility** | Uses heuristics instead of per-site scripts, so it works on many different checkout implementations. |

### Safety principles

- **You approve every payment on PayPal.** MannaPay never runs on `paypal.com`, never sees or enters credentials, and never approves a payment.
- **No surprise orders.** MannaPay only clicks something when you press a MannaPay button. Even then, it only clicks controls labelled *PayPal*. A generic **Place order** button is highlighted for you to press yourself, because on some stores it charges a saved payment method.
- **Minimal permissions.** `storage` and `activeTab`, plus a host permission for `paypal.com` so the extension can tell when you're on PayPal. The content script runs on web pages (not on PayPal) so it can detect checkouts. MannaPay doesn't request the `tabs` permission, doesn't read your browsing history, and has no server: all data stays in the browser's extension storage.

## Install (development)

1. `git clone` this repository.
2. Open `chrome://extensions` (or `edge://extensions`) and turn on **Developer mode**.
3. Click **Load unpacked** and select the repository folder.

Requires Chrome or Edge 110+ (Manifest V3).

## Project layout

```
manifest.json               MV3 manifest
src/lib/money.js            Amount and currency parsing, PayPal currency list
src/lib/detect.js           Checkout, PayPal, order and outcome detection (pure DOM functions)
src/lib/flow.js             Payment-flow records, amount verification, history
src/lib/settings.js         User settings (chrome.storage.sync)
src/content/content.js      Page analysis loop, assistance actions, in-page panel
src/background/service-worker.js
                            Per-tab state, badge, PayPal redirect/popup tracking, history
src/popup/                  Toolbar popup (current page, settings, recent payments)
icons/                      Toolbar icons (generated by scripts/make_icons.py)
test/                       Unit tests (jsdom) and an end-to-end test in Chromium
```

### How a payment is tracked

1. The content script analyzes the page and reports a summary to the service worker, which sets the badge (`PP` = PayPal available).
2. When you press **Pay with PayPal**, a *flow* is recorded with the merchant, total and currency.
3. The service worker sees the tab (or a PayPal popup opened from it) reach `paypal.com`, then return.
4. Back on the merchant site, the content script looks for a confirmation or cancellation. It reports the outcome, which is checked against the original total and saved to history.

Flows that never reach PayPal are dropped when you leave the checkout. Flows with no outcome expire after 30 minutes and are recorded as *Not confirmed*.

## Development

```sh
npm install
npm test            # unit tests (node:test + jsdom)
npm run test:e2e    # loads the extension in Chromium (Playwright) against test/fixtures
npm run icons       # regenerate icons (Python + Pillow)
npm run package     # dist/mannapay-<version>.zip for store upload
```

The end-to-end test serves the fixture checkouts locally and stubs out `paypal.com`. It covers detection, every assistance path, outcome confirmation, amount-mismatch flagging, auto-select, disabled sites and the popup. It writes screenshots to `test/e2e/screenshots/`.

To support a new checkout pattern, add a fixture under `test/fixtures/` that reproduces it, add a case to `test/detect.test.js`, then adjust the heuristics in `src/lib/detect.js`.
